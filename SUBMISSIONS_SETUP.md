# Student resource sharing setup

The home page contains the share form and receipt-based status sidebar. Submitted files stay private in R2 until an administrator approves them. Approved files appear in the Class 10 or Class 12 student-shared list on Study Materials. Once approved, the local admin service copies each file to Internet Archive under `community-uploads/<review-id>/` with an adjacent `info.txt`. The Archive copy is public. Discord and Reddit IDs appear in `info.txt` only if the student checks the separate public-credit opt-in; otherwise the contributor is anonymous. IDs remain visible privately to admins for review.

1. Apply `migrations/0002_student_submissions.sql` and then `migrations/0003_community_archive.sql` to the same Cloudflare D1 database used for analytics, then bind it to the Pages project as `ANALYTICS_DB`. If submission tables already exist, apply only migration 0003. It queues previously approved submissions for archiving and treats their earlier ID submissions as **not opted in**.
2. Create a **private** Cloudflare R2 bucket. Bind it to the Pages project as `SUBMISSIONS_BUCKET`. Do not expose the bucket through a public domain.
3. Set Pages secret `SUBMISSIONS_ADMIN_TOKEN` to a random string of at least 32 characters. The secret protects the admin review API and keys the upload rate limit. Keep it outside Git.
4. On the computer running `.local-admin/server.mjs`, set `SUBMISSIONS_ADMIN_URL=https://YOUR-SITE/api/submissions/admin` and `SUBMISSIONS_ADMIN_TOKEN` to the same secret. In the local panel, save your private Internet Archive S3 keys and Archive item prefix under **Resources → Private Archive connection**. Keep these keys outside Git. Restart the local panel and leave it running for the approval queue to transfer. Open **Submissions** after signing in with an allowed admin account.
5. Deploy the site. Test with a small PDF or image: submit on home page, copy the tracking code, confirm **pending**, inspect the file in the local admin panel, approve it, then confirm **approved** and a public download on Study Materials. The admin panel shows the Archive state and link after both the file and `info.txt` have been verified. Failed transfers retry automatically; admins can also press **Retry archive**.

`info.txt` contains the review ID, class, subject, resource type, original filename, MIME type, file size, submission and approval times, and Archive file URL. It never contains the tracking receipt or IP address. Rejected or pending files have no Archive copy. Internet Archive copies may remain accessible even after a resource is removed from this site; review the content and student consent before approval.

Uploads require the Cloudflare IP header, same-origin requests, and a valid PDF/JPEG/PNG/GIF/WebP signature. Limit: 20 MB per file and five attempts per IP per hour. User-controlled file names never become R2 storage paths. R2 objects are private; the public file route only serves approved rows. Anyone holding a receipt can see its status, so treat tracking codes as private. The local admin folder is ignored by Git; copy its updated files to any other authorized admin computer through the existing private process. Archive credentials, pending uploads, and the local admin authentication data stay outside the public repository.
